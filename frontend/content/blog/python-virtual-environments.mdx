Without virtual environments, every project shares the same packages, and that gets messy fast.

## Direct answer

A virtual environment is an isolated copy of Python tools and packages for one project. Create one with `python -m venv .venv`, activate it, then install packages with pip. Each project then has its own set of versions.

## Create and activate

```bash
python -m venv .venv
```

Activate it:

```bash
# macOS and Linux
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1
```

When active, your prompt usually shows `(.venv)`.

## Install packages

```bash
pip install requests
pip freeze > requirements.txt
```

## Leave and delete

```bash
deactivate
```

To delete it, remove the `.venv` folder. Your code is not affected.

## Why bother

- Avoids conflicts between projects needing different versions.
- Makes sharing easy with a `requirements.txt`.
- Keeps your system Python clean.
