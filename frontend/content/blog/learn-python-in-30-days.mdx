"Learn Python in 30 days" is a popular promise. Honestly: in 30 days you will not master Python, but you can learn the **fundamentals** and build small programs. Here is a realistic plan that takes about **20 to 30 minutes a day**.

## Direct answer

In 30 days you can learn the core of Python: variables, data types, conditions, loops, lists, dictionaries and functions, and write small programs like a guessing game or a to-do list. Practise every day, type the code yourself, and build something at the end of each week.

## Week 1: the basics (days 1-7)

- **Day 1:** Run your first program with `print("Hello")`. Learn what a program is.
- **Day 2:** Variables and numbers: `age = 20`, basic maths.
- **Day 3:** Strings: join, repeat, change case.
- **Day 4:** Getting input with `input()`, and converting types with `int()`.
- **Day 5:** Comparisons and booleans: `==`, `>`, `and`, `or`.
- **Day 6:** `if`, `elif`, `else`.
- **Day 7:** **Build:** a program that asks your age and tells you if you can vote or drive.

## Week 2: repeat and organise (days 8-14)

- **Day 8:** `while` loops.
- **Day 9:** `for` loops and `range()`.
- **Day 10:** Lists: add, remove, loop through.
- **Day 11:** Common list tools: `len()`, `sum()`, sorting.
- **Day 12:** Dictionaries: key and value pairs.
- **Day 13:** Mixing loops and conditions.
- **Day 14:** **Build:** a number guessing game (see [easy Python games](/blog/easy-python-games)).

## Week 3: functions and tidy code (days 15-21)

- **Day 15:** Functions: `def`, parameters, `return`.
- **Day 16:** Why functions matter: reuse and clarity.
- **Day 17:** Reading error messages and fixing bugs.
- **Day 18:** Strings in depth: slicing, `split`, `join`.
- **Day 19:** Reading and writing text files.
- **Day 20:** Importing modules: `random`, `math`.
- **Day 21:** **Build:** a quiz game that stores questions in a list of dictionaries.

## Week 4: a real project (days 22-30)

- **Days 22-23:** Pick a project (a budget tracker, a flashcard app, a text adventure) and plan it on paper.
- **Days 24-28:** Build it in small pieces, testing as you go.
- **Day 29:** Clean up your code and add comments.
- **Day 30:** Show it to someone and write down what you would add next.

Need ideas? See [Python projects for beginners](/blog/python-projects-for-beginners).

## Rules that make 30 days work

- **Type it yourself.** Copying and pasting teaches almost nothing.
- **Change every example.** Break it on purpose, then fix it.
- **Practise daily.** Twenty minutes every day beats two hours on Sunday.
- **Build early.** A tiny project every week keeps it real.
- **Stay in one resource.** Switching courses resets your progress.

## What day 30 looks like

You can read simple Python, write short programs, and search for solutions when you are stuck. That is a genuine skill. It is the start, not the end. After day 30, practise on projects, then pick a direction such as data, automation or web.
