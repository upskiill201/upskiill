One codebase or two?

## Direct answer

React Native lets you write one JavaScript or TypeScript codebase for iOS and Android. Native development uses separate codebases in Swift and Kotlin. React Native is usually faster to build and cheaper for most apps. Native is better for demanding performance or deep platform features.

## Comparison

| | React Native | Native |
| :--- | :--- | :--- |
| Codebases | one | two |
| Languages | JavaScript or TypeScript | Swift, Kotlin |
| Speed to market | faster | slower |
| Platform features | most, with some native code | all, immediately |
| Performance | good for most apps | best for heavy graphics |

## Good fits for React Native

- Business apps, marketplaces and content apps.
- Teams with web skills.
- Prototypes and MVPs.

## Good fits for native

- Games and heavy graphics.
- Apps that rely on the newest platform APIs.
